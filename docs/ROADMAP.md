# Octoii 产品路线图

更新：2026-11-17。当前排期以本文为准；具体工具契约见 [PRODUCT_TOOLS.md](PRODUCT_TOOLS.md)，已有桌面验收记录见 [DESKTOP_ACCEPTANCE.md](DESKTOP_ACCEPTANCE.md)。

## 产品方向

Octoii 是 run anywhere 的持久化 Agent。用户围绕一个任务与自己的 Octoii 持续协作，查看过程、介入操作、检查结果，并从另一台设备接续。

先做好 macOS 桌面和 iPhone 远程参与，再补 Windows / Android。桌面采用 Electron；手机框架和连接桥接仍待真机原型验证。现有 Web 保留，不要求各端共用一套页面布局。

保留 Beak 日志与快照、Siphon 持久执行、Octoii 自有 Agent 和已有 Claude 接入。OpenCode 作为自有 Agent 产品组织的主要参考，t3code 作为交互和开发流程参考；不以复制竞品全部功能作为完成标准，不重启外部多 Agent 产品线。

## 产品概念与组织边界

- **节点**：任务在哪台机器执行，连接、账号和权限属于哪个环境。
- **项目**：任务使用的工作目录及其指令、Git 和配置。允许无项目任务。
- **Thread**：持续推进的任务，包含对话、执行过程、待处理问题、子任务和结果。
- **上下文引用**：用户交给 Agent 的具体材料，如文件选区、diff 评论、终端输出、网页元素和历史 Thread 内容。
- **产物**：交付给用户的文件、HTML、图片和改动；优先使用现有资源引用，不新建成果数据库。

项目负责工作环境，系统状态表示执行进度；置顶、归档、Snooze 和搜索负责日常整理。暂不增加标签，也不预留 labels 字段。先验证现有组织方式，出现真实的跨项目分类需求后再评估。

桌面以任务列表、对话、辅助工作对象组织。Thread details 保持浮窗，保留布局避让和窄屏自动收起；不借路线图重新更改已确认交互。

Rust 已按 `core/`、`extensions/`、`apps/node/` 分层，Cargo 依赖与 CI 约束方向，见 [ARCHITECTURE.md](ARCHITECTURE.md)。暂不提取独立 UI 扩展包，前端在 `apps/web` 内维持模块边界。不因产品功能增加新的总线、插件框架或另一套运行时。

## 当前基础与缺口

“已实现”不等于已完成发布验收；自动化、内置浏览器、Electron 和手机真机结果分别记录。

| 能力 | 当前基础 | 下一步缺口 |
| --- | --- | --- |
| Agent 与工具 | 自有 Agent；统一 content / structuredContent / metadata；execute；explorer / general_purpose | 稳定性回归与真实任务验收 |
| Thread 整理 | 历史搜索与读取、重命名、置顶、归档、Snooze | 先验证现有入口，不添加标签 |
| 文件与 HTML | present_file、持久资源、主题联动预览、浏览器自检 | 文件审阅反馈统一；各端实际下载、展示验收 |
| 浏览器反馈 | 元素选取、截图、反馈草稿与发送已实现 | 统一引用交互；完整应用和手机验收，不重复实现 |
| Git 工作目录 | Git::create_worktree 准备原语已实现 | 尚无创建 RPC、thread.start 和界面闭环；未实现跨崩溃自动恢复 |
| 桌面 | Electron、节点发现与配对、随包资源与节点、隔离安装验证 | 干净 macOS 账号首装、正式签名公证及升级验收 |
| 远程与手机 | 节点配对、权限、隧道、Web 入口、共享客户端 | iPhone 真机跨网络连接和完整接续；原生框架未定 |
| 多机器 | 日志、快照和执行基础 | 不代表已实现复制、交接或远程子任务 |

## 推进顺序

按完成条件推进，不预设日期。每项优先复用现有实现，验收后单独提交；push 和合入 main 按用户授权执行。不恢复暂停的 goal。

### R0：稳定性基线

先处理最近全量测试中暴露的进程移除超时，再在此基础上增加功能。

- 调查 Siphon Thread 测试等待主进程移除超时的原因，区分测试同步问题与运行时问题；不通过扩大超时或忽略测试掩盖失败。
- 核对停止、等待人工输入、继续、节点重启的现有语义，修复有证据的问题。
- 2026-11-17 目录迁移验证：分层检查、格式、Clippy 通过；全量最后一轮 274 通过、3 忽略、1 失败。相同进程移除失败已在迁移前 HEAD 的完整 Siphon 测试集复现，尚未解决；这是基线问题，不标记为迁移新增回归或已修复。

验收：相关测试单独与完整测试集均通过；针对根因有回归覆盖。只有出现新改动或不稳定证据时才重复测试。

### R1：Thread 与工作目录闭环

第一项新增产品能力：用户创建任务时能明确选择在哪里工作。

拆分：

1. **R1a 后端准备与启动**：复用 P04a，定义新任务创建、目录准备、实际目录绑定和失败重试；用户输入保留，目录就绪前不执行 Agent。
2. **R1b 创建界面**：当前项目、其他目录、无项目任务；Git 项目可选择当前目录或新 worktree，并明确基准分支。Thread 显示实际工作目录和可识别的节点信息。
3. **R1c 生命周期与验收**：处理冲突、部分失败、客户端重连、节点重启以及用户删除任务。删除 Thread 不自动删除用户目录或未提交改动；首次只支持新任务隔离，不迁移运行中的任务。

验收：真实仓库中两个任务使用不同 worktree，改动互不干扰；源目录未提交改动不被悄悄带入；目录准备失败可诊断且不丢输入；重复提交/重连不重复启动任务或创建工作目录。发生无法自动恢复的准备操作时明确显示待处理现场，不盲目重跑。非 Git 目录和无项目任务仍可使用。

暂不引入独立 Workspace 管理层、自动合并或 worktree 池。先完成项目目录与独立 worktree 两种实际行为。

### R2：上下文引用与文件审阅

目标：用户能准确表达“请看这里”，Agent 获得用户实际指向的材料。

拆分：

1. **R2a 统一引用交互**：盘点已有文件附件、元素反馈和历史读取，复用现有消息结构，明确来源、必要的选中内容、用户评论和发送时机。新增字段只为实际缺口服务。
2. **R2b 文件与 diff**：从文件选区和改动行添加引用/评论到 Composer；支持查看、移除和跳回来源。已有文件树、预览、diff 继续复用。
3. **R2c 历史与失败处理**：发送失败保留草稿；成功仅清除本次提交内容；重开历史仍能理解当时的选区与评论。来源变化或消失时明确说明，不能把新内容冒充原引用。

验收：用户对真实改动选中一段并评论，发送后 Agent 能定位并完成修正；重新打开 Thread 可以看到原始反馈；权限不因引用扩大。长内容使用已有资源与按需读取机制，不自动把整份文件或全部 Thread 历史灌入模型。

本阶段不增加通用上下文服务或第二套附件存储。

### R3：终端与浏览器协作

目标：用户能观察、介入，并把反馈交回当前任务。

- 复用现有终端和浏览器，核对界面与 Agent 是否面对同一对象及其状态。
- 终端输出选区加入上下文；输入、停止、退出和重新打开的行为明确。
- 已有浏览器元素反馈接入统一引用体验；页面切换、选取取消和迟到结果不能污染新的草稿。
- 明确用户操作与 Agent 操作冲突时的行为；不为此先建立通用控制权框架。

验收：真实任务中启动服务、检查终端输出、浏览页面、选择元素反馈并完成修正；失败、关闭页面或终端退出时界面准确反映状态。内置浏览器做日常界面验收，Electron 原生行为另外验证。跨 frame 元素定位按实际任务需要推进，不列为本阶段默认前置项。

### R4：iPhone 远程接续

桌面主线形成稳定闭环后，先验证连接原型，再决定手机实现方式。

拆分：

1. **R4a 真机连接**：配对现有节点，在 Wi-Fi 与蜂窝网络间切换、断线重连、撤销访问；验证客户端复用与连接桥接边界。
2. **R4b 高频参与**：看进度、回答问题、审批、补充指令、停止和继续、查看文件与 HTML 产物。手机不要求先具备桌面完整工作台。
3. **R4c 两端一致性**：一端已处理的问题不再允许另一端重复提交；发送结果明确；长会话、软键盘、锁屏和切后台正确处理。

验收：同一真实任务在桌面启动、手机参与、桌面检查结果；手机离线或退出不影响节点执行，回来恢复正确状态。不得以桌面响应式截图或模拟器通过替代 iPhone 真机验收。

通知作为单独技术验证，不承诺客户端常驻后台，也不将通知送达等同于任务状态同步。

### R5：发布验收线

这条线与产品开发穿插推进，已有设备/签名条件时即可完成，不阻塞无关功能；未完成前不宣称正式发布就绪。

- macOS：干净账号首次安装、节点服务启动、应用移动、退出后任务持续、升级与数据保留、失败恢复、正式签名公证和分发。
- 连接：区分客户端断线与节点离线，重连不重复提交；撤销凭证生效。
- 执行：节点重启后显示真实恢复状态；不能安全继续的外部操作明确中断，不承诺任意副作用安全重放。
- 跨端：同一 Thread 的历史、待处理事项和产物一致；实际文件下载分别验收。
- iPhone：确定技术路线后记录实际安装分发与系统限制。

验收记录包含构建/提交、节点版本、设备、操作、结果和限制。旧节点上的成功不能代替当前随包节点验收。Windows / Android 在 macOS + iPhone 闭环后规划，按平台实际差异补齐。

## 后续：多机器交接与子任务分派

桌面和手机闭环稳定后再推进，不预设一台主电脑永久持有全部状态。

优先明确两种行为：

- **远程子任务**：明确目标、必要上下文、工作环境、父子关系及权限；重试不重复创建任务，结果可确认汇回。
- **任务交接**：历史和必要状态同步完成，目标工作目录就绪，在安全边界转移执行权；旧节点恢复上线不能与新节点同时执行。

先完成可验证的远程子任务，再设计更复杂的交接恢复。文件同步、聊天历史同步与执行权转移分别定义。终端、连接、授权不能假定可直接搬到另一台机器。

验收：两台真实机器完成分派与交接，并覆盖断网、重启、重复请求、超时和源端恢复。相关协议尚未确定，不提前建设分布式调度框架。

## 暂缓与不做

- Thread 标签及预留字段；尚无现有整理方式无法满足的明确需求。
- 独立 UI 扩展包、动态插件平台、插件市场；现阶段保留应用内模块。
- 外部多 Agent 统一运行、多订阅编排产品线；保留已有 Claude 能力。
- 通用 Workspace 管理、运行中 worktree 迁移、自动合并、环境池。
- 复杂调度、自动化平台、托管运行与计费作为当前客户端前置条件。
- 透明进程迁移、任意双向状态合并。
- 旧 IM、群组、家庭模式、General、Workbench 产品阶段；这些旧规划已废弃。
