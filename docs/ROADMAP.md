# Octoii 产品路线图

更新：2026-11-16

## 定位与当前优先级

Octoii 是 run anywhere 的持久化 Agent。用户选择在哪里运行它，并能从桌面和手机访问、查看结果、继续工作。

当前优先级是把桌面端和手机端做好：先让一个 Octoii 节点上的真实开发任务，在两端形成完整、稳定的使用闭环。多机器能力保留在产品方向中，但不作为首版客户端的交付前置条件。

本路线图以当前 Beak + Siphon 为基础，不要求重新设计内核，也不重新启动外部多 Agent 产品线。已有 Claude 接入继续保留。新增 Codex、Cursor 等原生 Agent 的统一接入暂缓。

## 决策状态

已确认：

- 优先交付桌面端和手机端。
- 首版真机原型及交付优先覆盖 macOS + iPhone，随后补齐 Windows / Android。
- 保留 Beak 的 append log、快照和 Siphon 的持久执行基础，按产品需要完善。
- 旧 IM、Workbench、General、群组及其阶段划分已废弃，不再作为产品或界面的需求依据。
- 当前聚焦 Octoii 自己的产品；外部多 Agent 产品线暂缓。

后续设计方向，尚未确定具体协议：

- 多机器支持带历史与状态同步的任务交接，以及跨机器子任务分派、结果汇回。
- 不把“只有一台主电脑保存全部状态，其他电脑只能作为 worker”作为本路线图的前提。
- 历史副本、任务执行权、父子任务关系需要分别定义，不能把有了历史副本等同于已经安全接管执行。

桌面壳已确定先采用 Electron，复用现有 Web 界面；先做桌面端，再推进手机端。移动端框架及后续原生能力范围需要单独确定。选型需要考虑后续 Windows / Android 支持，但不要求首版同时交付四个平台。归档文档中的技术选型不自动生效。

## 当前基础

以下是当前代码提供的基础，不代表所有能力已经达到客户端发布标准：

| 能力 | 当前基础 | 仍需产品验收 |
| --- | --- | --- |
| Agent 与开发任务 | Octoii、工具执行、项目和会话、已有模型与 Claude 接入 | 一项真实任务从输入到修改、验证和结果检查的完整体验 |
| 持久执行 | Beak 日志与快照、Siphon 请求和恢复机制 | 客户端退出、节点重启、执行中断时的明确状态和恢复行为 |
| 界面 | `apps/web`、`packages/client`、`packages/terminal` | 桌面和手机各自的布局、交互、安装与生命周期 |
| 历史 | Thread 列表、搜索、分页读取 | 两端查找、阅读和继续旧任务的体验 |
| 远程访问 | 节点配对、身份与权限、隧道及托管 Web 入口 | 真机跨网络连接、凭证撤销、断线重连 |
| 多机器 | 底层日志与快照可作为后续同步设计的基础 | 尚不能据此承诺自动复制、运行中迁移或跨机器分派已完成 |

## 第一阶段：桌面端与手机端

先明确两端的最小交互和运行方式，再围绕同一个真实任务迭代。桌面负责高效开展和检查开发工作；手机负责远程发起、查看、回答问题、停止和继续任务。两端共用协议和连接能力，但不强求共用一套页面布局。

### 1. 先确定客户端边界

需要形成一份短的实现决策：

- 桌面应用如何安装、启动、连接和升级本机节点；退出窗口是否影响节点必须明确。
- 手机如何添加并配对节点，如何切换网络、重新连接和撤销设备访问。
- 现有 Web 界面和 client 包分别复用到哪里；不预设删除 Web，也不重建另一套 Agent 内核。
- 围绕 macOS + iPhone 确定框架，记录后续 Windows / Android 的复用边界；推送和后台限制如何影响首版承诺。

验收：桌面和手机各自跑通“打开应用 → 配对节点 → 看到会话”的真机原型，技术选择及限制有记录。

当前代码核对结果与原型顺序：

1. `packages/client` 已通过 `ClientOptions.open` 和 `WebSocketLike` 隔离连接实现，可作为复用协议客户端的起点；仍需验证目标平台的运行时能力。
2. `apps/web` 的远程连接依赖浏览器 WASM、浏览器存储和浏览器网络能力，不能直接视为已经支持原生手机应用。相邻 `octoii-tunnel` 仓库有原生 Rust 实现，但此次检查未发现现成的 iOS / Android 绑定；移动端连接方式需要先验证。
3. 先实现 macOS Electron 壳，连接独立运行的本机节点，复用现有配对和会话界面；关闭窗口或退出 Electron 不停止节点。桌面通过现有 CLI 自动发现、配对本机节点，并可为默认 macOS Home 启动或首次安装 launchd 服务；节点二进制仍需预先安装，打包与升级随后完善。随后验证 iPhone 到现有节点的配对、会话读取和断线重连，再确定移动端框架与连接桥接的组合。
4. 连接验证通过后，两端以同一个会话完成输入、状态更新和重新打开后的恢复，再扩展完整界面。模拟器通过不能替代真机验收。

### 2. 桌面完成开发任务闭环

- 添加项目、配置或选择可用模型、创建和继续会话。
- 发送任务，看到真实执行状态、工具结果、提问与审批。
- 停止、补充说明和处理失败，明确哪些动作已完成、哪些没有完成。
- 查看文件、代码差异、终端输出和验证结果，必要时展开执行细节。
- 查找历史会话，使用键盘顺畅完成高频操作。

验收：在真实仓库中完成一次“提出修改 → 编辑 → 测试 → 检查差异 → 继续修改”的流程；关闭和重新打开客户端后仍能接续任务，不能依赖聊天页面存活来维持执行。

### 3. 手机完成远程参与闭环

- 配对自己的运行节点，清楚显示连接和节点状态。
- 阅读会话、发起和继续任务、查看当前进度与结果。
- 回答问题、处理审批、补充指令和停止任务。
- 阅读适合手机展示的代码差异、文件和工具输出。
- 正确处理软键盘、长会话、切后台、锁屏、弱网和网络切换。
- 将通知纳入实现评估；不通过要求手机常驻前台来保证节点继续工作。

验收：离开电脑后，通过手机完成“查看任务 → 回答问题或批准 → 查看结果 → 继续任务”；手机离线或被系统结束时不影响节点执行，回来后能恢复正确状态。

### 4. 两端一致性和发布准备

- 同一个会话在桌面和手机之间切换，内容、执行状态和待处理事项一致。
- 一端已回答的问题或审批，在另一端不再作为未处理事项提交。
- 断线重连不重复创建会话、不重复提交用户输入；发送失败与确认成功明确区分。
- 节点离线与客户端断线能区分，不用永久的“工作中”掩盖故障。
- 节点重启后，对于不能安全继续的外部操作明确显示中断，不把恢复等同于任意副作用重放。
- 验证配对撤销、升级与数据保留，以及两端的分发安装流程。

阶段出口：桌面和手机均在真实设备上完成上述场景，有可重复的验收记录和明确的已知限制；本地环境、真实远程网络和节点重启均包含在验收中。

## 第二阶段：多机器交接与子任务分派

这一阶段在两端客户端稳定后推进。先把用户行为和失败语义确定，再补协议与界面，不先增加分布式框架。

### 带历史与状态的交接

用户将一个任务从机器 A 交给机器 B 继续。历史同步是交接的条件之一，还需要：

- 明确交接的持久化位置，以及接收方已确认拥有的数据。
- 明确文件、工作区和运行环境如何就绪；聊天记录同步不等于工作文件同步。
- 在可安全交接的位置停止原执行方，确保同一任务不会在两台机器上同时产生副作用。
- 区分可携带的会话状态与必须在目标机器重新建立的进程、终端、授权和连接。
- 定义源端离线、接收失败和交接超时后的归属，禁止因超时直接产生两个执行者。

### 子任务分派

父任务可以将一项独立工作交给另一台机器上的 Octoii：

- 子任务获得明确的目标、必要上下文和工作环境，不默认复制所有历史与凭证。
- 保留父子关系、任务标识、进度和结果；重连或重试不能重复创建或执行同一项分派。
- 子任务结果汇回父任务，由父任务决定如何继续。
- 停止、失败、离线和重新连接有明确行为；父任务可以继续与用户交互。

待决定：任务执行权的转移协议、同步粒度、工作区准备方式、分派权限，以及结果汇回的确认机制。

阶段出口：两台真实机器之间完成一次安全交接和一次子任务分派，并验证断网、重启、重复请求和源端恢复上线不会造成双重执行或结果丢失。

## 暂缓

- 外部多 Agent 的统一运行与多订阅编排产品线。
- 通用群组、家庭模式、General 等旧规划。
- 在没有具体需求之前建设双向任意合并、透明进程迁移或复杂调度平台。
- 把托管运行、Pool、计费或复杂自动化作为首版桌面与手机的前置条件。

## 下一步

macOS Electron 壳已具备本机节点发现与配对、随包 Web 资源、独立启动与错误重试页面（见 `apps/desktop/README.md`）。已完成一轮真实模型任务、停止后继续、退出后恢复与 Git 差异验收，并修复最后会话位置恢复，详见 `docs/DESKTOP_ACCEPTANCE.md`。下一步补齐待验收场景，并推进安装分发与原生交互；iPhone 原型随后推进。桌面采用 Electron，移动端框架仍待确定。
