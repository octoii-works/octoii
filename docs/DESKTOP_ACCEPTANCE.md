## 发现与修复

原桌面壳重新打开窗口时总是加载根地址，虽然任务仍在运行、历史仍可访问，却不能直接回到刚才的会话。

现在由桌面主进程保存最后的应用路由：

- 复用 Web 的路由解析和序列化，不维护第二套会话路由格式。
- 按节点 Home 区分；显式指定连接地址时按 origin 区分，不将其他节点的会话直接恢复过来。
- 同一 Home 改变端口后仍可恢复会话；显式深链接和配对链接优先。
- 只保存根页面的规范化路由，不保存启动页面、外部地址或配对 URL。
- 用户明确切回新会话页时保存该选择。
- 小文件以原子替换写入，退出不依赖异步刷新；损坏或缺失的记录不阻止启动。

增加 4 项回归测试，覆盖重启与端口变化、节点隔离、新会话选择、凭证不落盘及损坏记录。桌面测试共 21 项通过，构建、全仓类型检查和 lint 通过。

### 本轮发现与修复

1. **浏览器选取按钮一直禁用。** 浏览器 resize 改了视口却没有通知页面列表订阅，客户端保留旧 `page.view`；而静态页面在设置新尺寸后也不一定立即产生 screencast 帧。现在 resize 完成后通知订阅，并停止/重新开始现有画面流以取得新尺寸的真实帧，不将旧帧冒充新尺寸。初次打开仍只启动一次画面流。真实 Chromium 回归在不修改 DOM 的情况下验证 DPR 2 → 1 的视口通知、帧编号和尺寸一致。
2. **Web 中 HTML 交付加载超时。** 当前验收浏览器 Chrome 157 中，HTTP 沙箱宿主创建的 Blob 子页面停留为空白；相同条件的 `srcdoc` 对照可渲染，且保持父页面不可访问、网络请求被阻止。共享宿主改用内部 `srcdoc`，删除 Blob URL 生命周期管理；外层仍为独立 HTTP 文档，双层 sandbox 与 CSP 不放宽。普通 headless Chrome 的 HTTP 嵌入测试在原实现也能通过，所以该测试属于结构覆盖，不伪称为问题的失败回归；本机验收浏览器的 A/B 对照是故障与修复证据。
3. **失败卡片操作入口。** 预览失败时保留卡片最小高度，使浮动操作有稳定的鼠标区域。
4. **两处展示歧义。** 同一会话的三次 thread 调用不再汇总成“三个会话”；浏览器反馈中的 JSON 使用代码块，防止 Markdown 将 URL 与后续字段误拼成可点击链接。已保存的旧消息不改写。
